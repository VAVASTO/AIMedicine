# Проверки

Проверки разделены на четыре уровня: автоматические тесты, эталонные сценарии, поиск по документу и обращения к LLM. Отчёты каждого уровня сохраняются отдельно.

## Как воспроизвести

```bash
bash scripts/run_checks.sh
python -m aimedicine.cli demo --mode offline --output reports/offline
python -m aimedicine.cli evaluate --mode offline --output reports/evaluation
python -m aimedicine.cli demo --mode live --output reports/live
python -m aimedicine.cli evaluate --mode live --output reports/evaluation_live
```

## Что проверяется

| Уровень | Проверка | Источник результата |
|---|---|---|
| Тесты | Структуры, время, поиск, правила, исправления, интерфейс | `reports/pytest*.xml` |
| Три offline-случая | Воспроизводимые переходы от старта к дню 3 | `reports/offline/summary.json` |
| Внесённые дефекты | Обнаружение ошибок и чистые контроли | `reports/evaluation/evaluation.json` |
| Поиск | Полнота нарезки и попадание ожидаемых оснований в выдачу | Отчёт retrieval в `evaluation.json` |
| Три live-случая | Выбор действий и аудит с Mistral | `reports/live/summary.json` и истории |
| Live-аудит дефектов | Проверка дозы до/после исправления и двух процедурных условий | `reports/evaluation_live/evaluation.json` |

Для поиска оцениваются автоматически нарезанные фрагменты всего извлечённого текста PDF; текст внутри растровых схем отдельно не распознаётся. Полнота извлечения и качество ранжирования — разные показатели. Результаты на небольшом наборе запросов характеризуют этот набор, а не все возможные клинические вопросы.

## Внесённые дефекты

| Вариант | Ожидаемая проблема |
|---|---|
| `wrong_dose` | Параметры отличаются от подтверждённого каталога |
| `irrelevant_citation` | Существующая ссылка не покрывает действие |
| `invented_citation` | Источник отсутствует |
| `ignored_allergy` | Не учтена известная немедленная аллергия |
| `drug_interaction` | Не учтено покрываемое взаимодействие |
| `ordered_ecg_without_result` | Назначение ЭКГ принято за известный QTc |
| `ignored_resistance` | После доступного посева сохранён препарат с R |
| `procedure_without_renal_result` | Не выполнено условие процедурной политики |
| `procedure_without_consent` | Не подтверждено согласие по процедурной политике |

Политики процедур имеют происхождение `demo_policy`. Они отделены от положений рекомендаций по пневмонии.

В `wrong_dose` копия эталонного плана получает дозу `999 г`. Исправление должно восстановить параметры того же действия, создать новую версию и сохранить исходную ошибку. Отдельный live-тест проверяет, обнаружила ли эту ошибку именно LLM. Искусственно внесённый дефект не считается самостоятельной ошибкой генерации модели.

## Как читать аудит

`findings` содержит подтверждённые замечания, `unverified_findings` — предположения LLM, не подтверждённые проверяемыми фактами. Их количества учитываются отдельно. Совпадение нулевого числа подтверждённых замечаний с непустым списком гипотез не считается чистым аудитом.

Исходные ответы модели и результаты проверки сохранены в истории. Проверка ограничена реализованными правилами: неподтверждённое утверждение за их пределами не объявляется автоматически ложным. Исправленные находки сохраняются со статусом `resolved`.

## Интерфейс и notebook

UI-тесты переключают трёх пациентов, версии результатов и внесённые дефекты. Отдельно проверяются публичный режим, согласованность манифеста завершённого запуска и отсутствие обращений к модели при просмотре. Notebook исполняется на сохранённых отчётах; его выводы должны соответствовать выбранному завершённому прогону.

## Результаты

На текущем корпусе выполнены три offline-случая: во всех итоговые открытые находки отсутствуют. Обнаружены 9 из 9 внесённых дефектов; три чистых контроля имеют 0 открытых находок.

На 10 размеченных запросах средний reference Recall@5 составил 0,85, reference Hit@5 — 0,90. Hit учитывает запросы, для которых найдено хотя бы одно ожидаемое основание. Ожидаемые опорные выдержки засчитываются только при покрытии их текста первыми пятью автоматическими фрагментами. Соседние фрагменты и последующая работа LLM в эту метрику не входят.

Полнота нарезки: обработаны 73 страницы; 98 текстовых фрагментов покрывают извлечённый текст 71 непустой страницы. Страницы 72–73 пусты. Тесты интерфейса: 3 passed.

Полный набор автоматических тестов: **262 passed за 28,561 с**. Notebook выполнен на завершённом live-прогоне: 6 из 6 кодовых клеток, 0 ошибок.

## Конкретный дефект, обнаруженный LLM

В процедурном тесте к копии эталонного плана добавлено назначение КТ с контрастом. Результат оценки функции почек удалён, согласие неизвестно. Политики сценария требуют эти сведения до процедуры. Метка внесённого дефекта, ожидаемые коды ошибок и заключения правил не передаются аудитору.

LLM самостоятельно вернула обе целевые находки:

| Цель | Исходный ответ LLM | Подтверждение по фактам |
|---|---|---|
| `contrast_renal_precondition_missing` | Найдена, `critical/open` | Подтверждена |
| `procedure_consent_missing` | Найдена, `critical/open` | Подтверждена |

Результат: **2/2** целей обнаружены моделью, **2/2** подтверждены; неподтверждённых гипотез LLM — **0**. Правила отдельно нашли ещё две проблемы: добавленное действие отсутствует в основном каталоге, а удаление почечных показателей оставило исходное назначение без необходимых данных. Эти две находки не засчитаны как обнаружение LLM.

Политики имеют происхождение `demo_policy`; тест проверяет соблюдение заданных процедурных условий. Источники: `reports/evaluation_live/evaluation.json`, раздел `llm_procedural_example`, и `fault_llm_procedure.json`.

## Ошибка дозы и повторный аудит

До исправления LLM правильно указала дозу `999 г`, действие `v1:ampicillin_iv`, код `catalog_parameter_mismatch` и источник `cap-dose-ampicillin`. Однако статус был `historical`, хотя ошибка оставалась актуальной.

Поэтому строгая метрика обнаружения открытого дефекта в исходном ответе равна **false**. Это ошибка статуса при верном содержательном обнаружении. Верхнеуровневые `llm_detected_wrong_dose` и `verified_wrong_dose_detected` также равны `false`: подтверждение правилами не засчитывается как полное самостоятельное обнаружение моделью.

Отдельная проверка подтвердила фактическую проблему и нормализовала статус в `open` (`before.rule_verification.target_open_confirmed=true`). Исправление восстановило параметры каталога в новой версии плана.

После исправления LLM верно вернула исходную находку со статусом `resolved`. Актуальных критических находок — **0**, неподтверждённых гипотез — **0**. Первоначальная доза и история исправления сохранены.

Источник: `reports/evaluation_live/evaluation.json`, раздел `llm_example`, и `fault_llm_before_after.json`.
