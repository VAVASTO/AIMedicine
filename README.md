# AIMedicine

Система поддержки врачебных решений: поиск по клиническим рекомендациям, составление плана, пересмотр по новым данным и независимый аудит. В демонстрации — три синтетических взрослых пациента с внебольничной пневмонией.

[Открыть демонстрацию](http://51.250.20.30:8502) · [Архитектура](docs/architecture.md) · [Проверки](docs/validation.md)

## Как работает

```text
Карточка пациента → поиск по PDF → план → проверка
                                           ↓
                         состояние на 3-й день
                                           ↓
                  продолжение или пересмотр → аудит истории
```

1. Пациент поступает в структурированном виде: установленный диагноз, тяжесть, аллергии, препараты, измерения с датами. Будущие результаты скрыты от планировщика.
2. BM25 ищет основания по автоматически нарезанному тексту всех страниц PDF. Соседние фрагменты сохраняют контекст таблиц и рекомендаций.
3. LLM выбирает действия из каталога и объясняет их найденными источниками. Программа подставляет параметры из каталога и проверяет ограничения. Источники всех кандидатов заранее в контекст не добавляются.
4. Сценарный симулятор создаёт состояние на третий день. При улучшении план продолжается; при новых проблемах повторяются поиск и планирование.
5. Отдельная LLM проверяет историю без готовых выводов правил. Подтверждённые замечания и непроверенные предположения сохраняются раздельно. Исправления создают новую версию плана.

В первом случае ожидается положительная динамика. Во втором исходная аллергия ограничивает выбор. В третьем тестовый сценарий задаёт отсутствие улучшения и устойчивость к фактически выбранному препарату; результат посева становится доступен на третий день и требует пересмотра. Тесты с намеренно внесёнными ошибками отделены от этих трёх случаев.

## Источники и границы

Основной источник — [«Внебольничная пневмония у взрослых», редакция 2024 года, ID 654_2](https://spulmo.ru/upload/KR-vnebolnichnaya-pnevmoniya-u-vzroslyh-2024.pdf). PDF, извлечённые страницы и SHA-256 находятся в `data/source/`; поисковые фрагменты — в `data/document_chunks.json`. Для проверки связей «действие — источник» отдельно сохранены 33 точные опорные выдержки в `data/chunks.json`. Они не составляют поисковый индекс. Инструкции к препаратам и локальные процедурные политики имеют отдельное происхождение. Текст внутри растровых схем отдельно не распознаётся.

Каталог ограничен 15 действиями; дозы, пути и частоты заданы по источникам. Симулятор воспроизводит сценарии с фиксированным seed. Покрытие взаимодействий и проверяемых условий ограничено явными правилами; модель может предлагать неподтверждённые замечания. Результаты оцениваются на небольшой синтетической выборке.

## Запуск

Python 3.10+. Из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock.txt
python -m aimedicine.cli demo --mode offline --output reports/offline
bash scripts/run_ui.sh
```

Локальный интерфейс доступен по адресу `http://127.0.0.1:8501`. Публичная служба и её управление описаны в [инструкции](docs/public-demo.md). Notebook `notebooks/demo.ipynb` показывает завершённый live-прогон либо явно обозначенный offline-прогон.

Для live заполните `MISTRAL_API_KEY` в локальном `.env` по образцу `.env.example`:

```bash
python -m aimedicine.cli demo --mode live --output reports/live
```

Планировщик использует `ministral-8b-latest`, аудитор — `ministral-14b-latest`; обе модели задаются настройками. Offline использует эталонную политику для проверки системы. Ошибки live сохраняются отдельно и не заменяются offline-ответом.

## Проверки

```bash
bash scripts/run_checks.sh
python -m aimedicine.cli evaluate --mode offline --output reports/evaluation
python -m aimedicine.cli evaluate --mode live --output reports/evaluation_live
```

Пройдены **262 автоматических теста**. Правила обнаружили 9/9 внесённых дефектов. В отдельном live-примере LLM самостоятельно нашла два нарушения процедурных политик: назначение КТ с контрастом без результата оценки функции почек и без зарегистрированного согласия. Обе находки подтверждены проверкой фактов. Это тестовая мутация плана с отдельными политиками, а не положение КР по пневмонии.

Также проверено исправление дозы `999 г` с сохранением исходной ошибки в истории. Три live-случая завершены; у двух остались неподтверждённые гипотезы аудитора. Результаты поиска, исходные ответы LLM, статусы находок и ограничения приведены в [отчёте проверок](docs/validation.md).
